# FR-Harness 交互式 CLI 与 Windows Release 设计

**日期：** 2026-08-01  
**状态：** 已经用户逐段批准，等待文档终审  
**交付路线：** 助教说明中的方案一，以 GitHub Release 托管 CLI 产物；现有 WebUI 仅作为本地可选功能

## 1. 目标与范围

FR-Harness 的最终主要交付物是 Windows x64 独立可执行文件。助教无需安装 Python，即可通过一个持续运行的中文交互式控制台完成模型配置、创建修复任务、审批危险操作、查看测试反馈、恢复中断任务和查询历史记录。

本轮不开发公网 WebUI，不提供公网服务地址，也不增加公网认证系统。现有本地 WebUI 保留为 `serve` 子命令的可选能力。Agent 主循环、护栏、记忆、反馈与审批逻辑继续保持唯一实现，CLI 不复制这些机制。

首版明确不支持：非 Windows 平台发行包、Windows ARM64、多进程并发执行、多用户、任意 shell、后台任务队列和公网 WebUI。

## 2. 启动与主菜单

以下两种方式均进入交互式主菜单：

```powershell
.\fr-harness.exe
.\fr-harness.exe run
```

首次启动时，程序先检查应用配置。配置缺失或无效时，自动进入现有 `setup` 流程；完成供应商选择、模型配置、隐藏输入 API Key 和 `doctor` 自检后，回到原本的主菜单，不要求用户重新运行命令。

配置取消、API Key 为空或自检失败时，不创建任务。双击启动发生程序级错误时，程序等待用户确认后关闭，避免窗口闪退。

主菜单固定为：

```text
FR-Harness

模型：已配置模型的非秘密摘要
配置：正常

1. 新建修复任务
2. 查看历史任务
3. 配置与自检
4. 退出
```

“配置与自检”复用既有 `setup`、`doctor` 和凭据管理能力，不建立第二套配置逻辑。主菜单不得显示 API Key。

## 3. 新建任务流程

### 3.1 工作区与目标

工作区默认使用启动终端的当前目录。用户直接回车确认，也可以输入其他相对路径或绝对路径。程序解析后显示最终目录并要求确认；目录不存在、不是目录或不可访问时，留在输入步骤重新选择，不自动创建目录。

修复目标采用单行输入。空字符串或只包含空格时不创建任务。复杂业务规则应保存在目标项目的 README 和测试中，由 Agent 读取。

开始前显示工作区名称、目标和最大轮数，用户可开始、重新输入或取消。

### 3.2 任务级 pytest 权限

开始执行前，CLI 单独说明 pytest 会执行工作区中的 Python 代码，并要求用户确认该工作区可信。批准结果与 task id 绑定并持久化；同一任务后续可以重复运行固定 pytest，不再反复询问，任务恢复后也不重新询问。

拒绝 pytest 权限时，不执行 Agent；尚未产生有效动作的任务取消并记录原因。pytest 权限不能跨任务复用。

### 3.3 运行进度

默认显示中文进度、动作摘要、审批、测试摘要和最终结果，不显示 UUID、原始 Action JSON、完整提示词或完整 API 响应。例如：

```text
[第 1/8 轮] Agent 正在分析
[读取文件] README.md
[准备修改] src/cart.py
```

技术详情只能由用户主动选择查看，并且同样经过脱敏。

## 4. 文件覆盖审批与 diff

新建文件沿用现有规则直接允许；每次覆盖已有文件都必须单独审批，一次批准只能消费一次。

默认审批摘要包含文件相对路径、修改原因、新增行数和删除行数。用户可以查看统一 diff，再批准或拒绝：

```text
需要审批：修改已有文件

文件：src/cart.py
原因：修复金额舍入错误
变化：新增 4 行，删除 2 行

[D] 查看完整差异
[A] 批准本次修改
[R] 拒绝并取消任务
```

diff 使用 Python 标准库生成，不调用外部命令。长 diff 分页或按明确上限截断，并提示内容未完整显示。diff 内容必须经过凭据脱敏。拒绝覆盖后，任务进入“已取消”，不能从历史菜单恢复执行。

## 5. pytest 反馈

pytest 继续通过固定参数数组和 `shell=False` 执行，并禁用 `.pytest_cache`。退出码是通过或失败的唯一客观依据。

失败时默认显示通过数、失败数、失败测试名称和不超过 2,000 字符的反馈摘要。用户可以查看经过脱敏的完整输出；完整输出设置 100 KB 上限，超过上限时明确标记截断。

提供给 LLM 的上下文仍只使用 2,000 字符摘要，完整日志不直接注入模型。失败反馈写入记忆后，Agent 自动进入下一轮修复；查看完整日志是可选操作，不改变客观反馈结果。

## 6. 任务结束与历史记录

单个任务成功、失败、取消或暂停后显示目标、轮次、修改文件数、测试结果、耗时和中文停止原因，然后返回主菜单，不关闭 CLI。

历史列表使用序号、目标摘要、工作区名称、中文状态和轮次，不以 UUID 作为主标题。UUID 只放在技术详情中。

历史任务权限如下：

- “等待审批”可以重新进入文件审批流程。
- “已暂停”或上次窗口异常关闭留下的“执行中断”可以恢复。
- “已成功”“已失败”“已取消”只能查看，不能继续执行。
- 恢复任务保留轮次、记忆、审计、pytest 权限和尚未消费的审批。
- 恢复不得重复执行已经完成的文件写入。

## 7. 错误与中断处理

### 7.1 可恢复错误

网络超时、HTTP 429、模型服务暂时不可用和用户按下 `Ctrl+C` 时，任务进入新增的 `paused` 状态。用户可以从历史任务继续。

pytest 运行期间收到中断时，CLI 终止本次测试进程并记录“测试被用户中断”，不得将其误判为通过或普通测试失败。

窗口被直接关闭后，下次启动将遗留的 `running` 任务显示为“执行中断”。首版不支持同时运行多个 EXE 实例，避免两个进程恢复同一任务。

### 7.2 不可恢复错误

以下情况进入“已失败”，只允许查看：

- 达到最大轮数。
- 连续生成完全相同动作。
- 工作区路径逃逸。
- LLM 持续返回非法 Action。
- 领域模型或工具参数非法。

### 7.3 程序级错误

数据库无法打开、迁移失败或应用数据目录不可写时，显示中文摘要并停止启动 Agent。错误信息不得包含 API Key、完整请求头、完整供应商响应或不必要的本机路径。

## 8. 代码边界

### `cli.py`

负责参数解析和模式选择。无参数或 `run` 进入交互主菜单；保留 `setup`、`doctor`、`serve`、`test`、`credential`、`--help` 和 `--version`。

### `console.py`

负责中文主菜单、输入、确认、进度、审批、diff、测试摘要和结果展示。它不直接访问 SQLite，也不直接调用 LLM。

### `task_service.py`

负责创建任务、逐轮驱动 Agent、协调终端审批、恢复任务和查询历史。WebUI 与 CLI 继续复用同一 Agent、Database、Guardrails 和 ToolDispatcher。

### `app_paths.py`

通过系统接口解析用户应用数据目录。源码测试、Docker 和 CI 可以通过环境变量覆盖，不在代码中硬编码用户名或绝对路径。

### `db.py`

增加 `paused` 状态、任务级 pytest 权限和兼容旧数据库的自动迁移。文件覆盖继续使用现有一次性审批记录。

### `tools.py` 与 `feedback.py`

将给 LLM 的摘要和供用户按需查看的完整日志分离。完整日志脱敏并限制为 100 KB。

调用关系：

```text
cli.py
  -> console.py
      -> task_service.py
          -> Agent
              -> LLM / Guardrails / Tools / Memory
          -> Database
```

## 9. 应用数据与凭据

Windows EXE 默认将非敏感配置、SQLite 和日志保存在当前用户的本地应用数据目录下的 `FR-Harness` 子目录。目录通过系统接口动态解析，不写死用户名。

API Key 只保存在 Windows Credential Manager。它不得写入应用数据目录、SQLite、日志、diff、终端输出或异常信息。待修复项目保持原位置，不复制到 FR-Harness 数据目录。

本地 WebUI 通过 `fr-harness.exe serve` 启动，并复用相同配置与数据库。最终作业提交不提供公网 WebUI 地址。

## 10. 离线演示

Release 增加：

```powershell
.\fr-harness.exe demo
```

演示只使用临时目录和 MockLLM，不读取真实 API Key，不访问网络，验证并输出：

```text
危险操作审批：PASS
失败反馈纠错：PASS
一次性文件审批：PASS
任务级 pytest 权限：PASS
```

源码模式下的 `test` 继续运行完整 pytest。冻结后的 EXE 执行 `test` 时，明确提示 Release 验收应使用 `demo`，不能声称 EXE 内包含仓库测试源码。

## 11. Windows Release

首版只发布 Windows 10/11 x64：

```text
FR-Harness-v1.0.0-windows-x64.zip
├─ fr-harness.exe
├─ 快速开始.txt
└─ SHA256SUMS.txt
```

使用 PyInstaller `--onefile` 构建。EXE 支持：

```text
fr-harness.exe
fr-harness.exe run
fr-harness.exe setup
fr-harness.exe doctor
fr-harness.exe demo
fr-harness.exe serve
fr-harness.exe --version
fr-harness.exe --help
```

没有商业代码签名证书时，Release 必须说明 EXE 未签名，并提供 SHA-256 校验值。

## 12. CI 与发布门禁

推送 `v1.0.0` 标签后，GitHub Actions 的 Windows job 必须：

1. 安装依赖并运行完整 pytest。
2. 构建单文件 EXE。
3. 使用隔离的临时应用数据目录执行 `--help`、`--version` 和 `demo`。
4. 启动 `serve` 并验证本地 HTTP 200。
5. 扫描输出与日志，确认测试凭据没有出现。
6. 生成 ZIP 和 SHA-256 校验文件。
7. 创建 GitHub Release 并上传产物。

发布成功条件是：全量测试通过、离线演示四项 PASS、EXE 在未安装项目源码的 Windows 环境中可启动、可选本地 WebUI 返回 HTTP 200、日志无测试凭据、Release 页面和附件可公开访问。

## 13. 测试矩阵

至少覆盖以下确定性测试：

- 首次启动自动 setup，成功后返回主菜单。
- 当前目录默认值、非法目录重试和空目标拒绝。
- pytest 权限按任务持久化且不跨任务复用。
- 每次覆盖文件单独审批，一次批准不能重复消费。
- diff 摘要、完整 diff、截断、拒绝和脱敏。
- pytest 摘要与完整日志分离，完整日志截断并脱敏。
- 成功、失败、取消、暂停和执行中断的中文展示。
- 等待审批和暂停任务可以恢复，终态任务不能恢复。
- `Ctrl+C` 不误报成功，不重复文件副作用。
- AppData 路径可在测试中覆盖，代码不含用户名或固定绝对路径。
- PyInstaller EXE 的帮助、版本、离线演示和本地服务冒烟测试。

## 14. 验收场景

助教从 GitHub Release 下载 ZIP，校验 SHA-256，解压并双击 EXE。首次启动完成模型配置后进入主菜单，选择一个可信 Python 项目，输入单行修复目标，批准该任务运行 pytest。Agent 读取项目，提出文件修改；助教先查看 diff，再批准单次覆盖。pytest 首次失败时 CLI 显示摘要并允许查看完整日志；Agent 获取反馈后继续修复，最终测试通过。任务结果进入历史记录，CLI 返回主菜单。

不使用真实模型时，助教可以执行 `fr-harness.exe demo`，离线看到四项 PASS，从而验证治理、反馈和审批机制不是只靠提示词实现。
