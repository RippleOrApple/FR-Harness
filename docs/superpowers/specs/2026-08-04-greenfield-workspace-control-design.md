# 空工作区任务控制设计

## 问题

当前控制器在每次 `write_file` 后都要求下一步执行 pytest。对于空工作区，模型先创建源码时测试文件尚不存在，pytest 返回 `no tests ran`；由于上下文没有工作区文件清单，模型可能反复改写源码并耗尽轮次，无法完成新项目创建任务。

## 目标

让同一个 Agent 同时可靠支持已有项目修复和空工作区创建：模型能够知道工作区是否为空、当前有哪些文件以及是否已有 pytest 测试文件，并根据状态选择创建文件或运行测试。

## 上下文清单

每轮调用模型前，控制器扫描工作区并向上下文加入相对文件路径清单：

- 仅提供文件名和相对路径，不读取额外文件内容。
- 忽略 `.git`、`.venv`、`__pycache__`、`.pytest_cache`、`.mypy_cache`、`.ruff_cache` 和覆盖率缓存目录。
- 最多提供前 100 个稳定排序的路径，避免大型项目无界占用上下文。
- 空清单明确标记为“空工作区”，要求模型根据目标使用 `write_file` 创建源码和测试，而不是猜测 `README.md` 或 `app.py`。

## 测试状态控制

控制器通过路径判断是否存在 pytest 测试文件：文件名满足 `test_*.py` 或 `*_test.py`。

- 最近动作是 `write_file` 且已有测试文件：下一步必须运行 pytest，保持原有客观反馈约束。
- 最近动作是 `write_file` 但没有测试文件：下一步必须创建测试文件，不允许运行 pytest，也不应重写刚创建的源码。
- 最新 pytest 反馈包含 `no tests ran` 或 `collected 0 items`：下一步必须使用 `write_file` 创建 pytest 测试文件。
- pytest 通过后仍只允许模型使用 `complete` 结束任务。

这些规则通过控制器系统消息约束模型，不绕过现有 Action、审批、护栏或工具边界。

## 错误反馈

读取不存在文件时，如果工作区为空，工具结果明确提示“工作区为空，请根据目标创建文件”；非空工作区继续提示依据已有文件、README 或 pytest 反馈选择路径。

## 测试

- 文件清单稳定排序、忽略缓存目录并限制为 100 项。
- 空工作区上下文明确要求创建源码和测试。
- 没有测试文件时，源码写入后的控制器要求创建测试文件。
- 已有测试文件时，源码写入后的控制器仍要求运行 pytest。
- `no tests ran` 反馈要求创建测试文件。
- 已有 Agent、审批、WebUI、Release 和安全测试全部通过。
